## 1. 问题一：模块之间缺少内在关联 → 增加「一键迁移并建链」

### 参考对象
用户提到的 "wincleaner" 实为 **WindowsClear（愚公移盘）** `github.com/tanaer/WindowsClear`。
它的动线是**一条直线**：`扫描大文件夹 → 勾选 → 选目标根目录 → 点「执行迁移」` →
跨盘移动 + 自动建立目录联接，一次完成，用户全程停在一个页面。

我们此前的动线是 `扫描页 → 切到迁移页 → 再点开始`，多了一次跳转与一次确认，**且没有任何跨页衔接**。

### 实现（对齐该动线）

1. **扫描页新增「一键迁移并建链」横条**：目标根目录（记忆上次选择）+「我理解风险」+ 两个按钮。
2. 勾选条目 → 点「一键迁移并建链」→ 在**扫描页原地**完成
   `预检（零写入） → 复制 → 校验 → 停车 → 建立目录联接 → 写台账 → 刷新记录`，
   状态直接显示在扫描页底部，列表的「已迁移」列就地刷新。
3. **表格每行新增「一键迁移并建链」按钮**：单条也能一键执行。
4. 保留「仅加入队列（高级）」：把条目送到迁移页并**自动跳转**过去 —— 用户再也不会怀疑"按钮没反应"。
5. 两条入口**复用同一段代码**（`MigrateViewModel.RunQueueAsync`），不存在"一键路径"和"迁移页路径"行为不一致的可能。
6. **记录页新增「重建链接」**：源路径已空（链接被手工删掉/还原后又想再迁）时，用记录里的
   「源 → 目标」一步补回链接 —— 这是"迁移 → 建链"动线在记录页的补偿入口。
   源路径上有真实目录时**硬拒绝**，绝不覆盖。

> 一键路径**不会**替用户接受风险：遇到警告名单等需确认项，会明确报
> 「存在需要确认的风险项」并指向扫描页那个「我理解风险」勾选框；勾选后才继续。

## 2. 问题二：部分页面内容无法正常展示（迁移队列等）

### 两个原因，都修了

**原因 A（崩溃，日志实证）**：`ScanViewModel.RemoveRoot` 空引用。
```csharp
Roots.Remove(SelectedRoot);          // ← 从集合移除 → ListBox.SelectedItem 变 null
if (!SelectedRoot.IsPreset)          // ← 双向绑定已把 null 回写 → NullReferenceException
```
**修法**：先取局部变量 `var root = SelectedRoot;`，后续一律用局部变量，并主动清空选中。
`R8_GuiFixTests.移除扫描根目录_不得空引用_并真的移除` 为回归守护。

**原因 B（布局把表格挤没了）**：迁移页有 4 个「高度由内容决定」的区域（Auto 行）围着 1 个队列区（`*` 行）。
按实际字号/边距复算：Auto 行合计约 **640px**，而 780px 窗口的内容区只有约 717px →
队列区只剩 **~77px**，扣掉表头（30px）只剩 **~45px** → **只看得见表头，一行数据都看不到**。
这正好解释了用户说的"迁移队列无法正常展示"。

**修法（三条同时上，防止任何单点回归）**：
1. 选项区压缩：4 个复选框从 4 行改 **2 列 × 2 行**；两个数字框并排（省下约 90px）。
2. 干跑预览 **默认折叠**（`IsExpanded="False"`）：展开态固定 150px 会直接吃掉队列高度（省下约 180px）。
3. 队列/结果表格加 **`MinHeight`**（迁移 150 / 扫描 150 / 记录 150 / 链接 120），任何窗口尺寸下都不会消失。
   窗口 `MinHeight` 提到 **680**（原 580，无法容纳完整页面）。

同类问题在链接页也存在（能力矩阵 5 个类型 × 3 行 ≈ 215px），已压成**一行一类型**（名称+状态+原因同行，建议放 ToolTip）。

修完后迁移页队列区稳定拿到 **~290px**（可见约 8 行）。

## 3. 问题三：文本框与文字字号不统一

**根因**：各处写字面量字号 —— `Label 12 / Hint 12 / 正文 13 / 区块标题 14 / 表格 12 / 品牌字 20`，
混排后基线参差；且中文在 12–13px 一档明显偏小。

**修法**：在 `Themes/Shared.xaml` 建立**四个字号标尺**，任何视图都不许再写数字字面量：

| 档位 | 值 | 用途 |
|---|---|---|
| `FontSizeTitle` | 20 | 页面主标题 |
| `FontSizeSection` | 14 | 区块标题 |
| `FontSizeBody` | **13.5** | 正文、输入框、按钮、复选框、下拉框 |
| `FontSizeSmall` | 12.5 | 表格、提示、次要标签 |

同时统一：字体族改为 `Microsoft YaHei UI, Segoe UI`（中文优先，界面观感一致）、
`TextRenderingMode=ClearType`、表格 `RowHeight 32 / ColumnHeaderHeight 32`。

**两条测试守护**：
* `界面_不得再出现数字字面量字号_必须使用统一标尺`（正则扫全部 XAML）
* `字号标尺_四个档位齐备且递增`（含"正文不小于 13px"的下限断言）

## 4. 问题四：点击目录复制路径 / 打开所在文件夹

### 实现

* **表格每行的路径列变成可点击链接**：单击 = **复制路径**；右侧紧邻一个「打开」小按钮 = **打开所在文件夹**。
  鼠标悬停显示下划线 + ToolTip 说明，长路径自动裁剪不会撑破列宽。
* **双击整行 = 打开该行主路径所在文件夹**（点行内按钮/复选框时不触发）。
* 覆盖四张表：扫描结果、迁移队列（源 + 目标两列）、迁移记录（源 + 目标）、已存在的链接。
* 执行复制后**外壳底部显示一行即时提示**「已复制路径：…」，4 秒后自动消失。

### 一处必须写下来的技术坑

双击为什么不用 XAML 的 `MouseBinding`？
**`InputBinding` 不在可视树上**，既拿不到 `DataContext`，也解析不了
`RelativeSource FindAncestor` —— 写了也不生效。因此双击必须落在 code-behind。
为了不让 code-behind 按类型 switch，抽象了 `IPathRow`（四个行模型各自实现 `PrimaryPath`），
交互逻辑集中在 `DataGridRowActions`。

## 5. 顺带修掉的两个真实缺陷

### 5.1 CLI 在管道场景直接崩溃（较严重）

`Program.OpenStandardWriter` 用 `new FileStream(new SafeFileHandle(GetStdHandle(...)))` 包装句柄，
在 **MSYS/Git Bash 与部分 CI 的管道**上抛异常；而这行代码在 `try` **之外** →
异常逃出 `Main` → 进程崩溃并打印 .NET 堆栈。

**实证**（修复前）：
```
$ ./dirporter.exe copy --engine robocopy ...
   at DirPorter.App.Program.OpenStandardWriter(Int32 handleId)
   at DirPorter.App.Program.RunCli(String[] args)
   at DirPorter.App.Program.Main(String[] args)
```
**修复**：优先用 `Console.OpenStandardOutput()`（能正确处理控制台/管道/文件三种情形），
失败再退回句柄包装，最后退回丢弃输出；并且**保证这条路径永不抛异常**；
`Main` 外层再加一道兜底，CLI 模式绝不把 .NET 堆栈甩给用户。

### 5.2 单元测试在往用户真实数据目录里写东西

实测发现 `%ProgramData%\DirPorter\runs\` 里堆着**测试产生的 journal**，
`migrations.json` 也被测试追加过记录（走 Journal / 迁移记录的用例共用进程级数据根）。

**修复**：新增 `TestEnvironment`（`[ModuleInitializer]`，保证早于任何测试与静态构造执行），
把 `DIRPORTER_DATA_ROOT` 指向 `%TEMP%\dirporter-tests-data`。
测试与用户数据从此彻底隔离 —— 也正因如此，才敢在测试里跑**真实的端到端迁移**。

## 7. 未做 / 已知限制（不假装）

1. **WindowsClear 那种"只扫 AppData 大户并按占比排序"不是本工具的定位** —— 本工具面向
   **任意目录**，因此没有照搬它的 10% 占比筛选。一键动线已对齐，扫描维度保持通用。
2. **一键路径遇到需确认项不会自动放行**：需要用户在扫描页勾选「我理解风险」。
   这是刻意保留的安全闸门（WindowsClear 在此处是直接放行，我们不跟随）。
3. **记录页的「重建链接」不做批量**：一次一条，且源路径存在真实目录时硬拒绝。
4. **表格行内按钮是文字按钮（「打开」）而非图标**：避免引入图标字体依赖与 DPI 模糊。
5. `%TEMP%` 下仍可能残留少量测试目录（迁移后源路径是 junction，
   `Directory.Delete(recursive)` 未必能清干净）；已用工具自身的 `cleanresidue` 语义规避删除风险，
   但测试清理不属于产品路径，未再加固。
