## 1. P0 表格渲染事故（一个隐藏 bug 解释用户两个抱怨）

### 现象与根因

用户：「扫描后没有给出扫描结果」「无法选择要迁移的条目（复选框）」。

根因在 `Themes/Shared.xaml` 的 `DataGridRow` ControlTemplate：R10 重写选中态时误用了
**裸 `<ContentPresenter />`**。`DataGridRow` 继承自 `Control`（不是 `ContentControl`，
**没有 Content 属性**），正确元素是 **`<DataGridCellsPresenter />`**。

后果：单元格呈现器从未进入可视树，**四张表格（扫描 / 迁移 / 记录 / 链接）整表不渲染任何单元格**：
行还在、行高还在、hover/选中背景还在，但没有任何内容、没有复选框。

而这一切**没有任何报错**：XAML 能解析、程序能跑、日志干净。R10 的 444 条测试也全绿：
- 静态扫描测试查的是资源键 / 字号，不查模板元素结构性；
- STA 构造测试只验证「能 new 出来」，不验证「画得出来」。

### 修复

```xml
<ControlTemplate TargetType="DataGridRow">
    <Border x:Name="Bd" Background="{TemplateBinding Background}" ...>
        <DataGridCellsPresenter ItemsPanel="{TemplateBinding ItemsPanel}"
                                SnapsToDevicePixels="{TemplateBinding SnapsToDevicePixels}" />
    </Border>
    ...
```

- `ItemsPanel="{TemplateBinding ItemsPanel}"` 是星号列宽度分配（DataGridCellsPanel）的前提，必须带上。
- 最小版即可：项目未用行头 / 行详情 / 冻结列，不需要官方完整模板里的 SelectiveScrollingGrid。
- `DataGridCell` 模板（ContentControl）用 `ContentPresenter` 是正确的，**未动**，并加了反向静态守卫防止有人"顺手改错"。

### 防回归（本次事故的最大教训：测试要能看见"画不出来"）

三层守卫，都已落地：

1. **静态扫描**（`R11_DataGridRenderAndSelectionTests`）：
   - `DataGridRow` 模板必含 `DataGridCellsPresenter`、不得含 `ContentPresenter`；
   - `DataGridCell` 模板反向约束；
   - 断言前先剥掉 XML 注释（R10 的教训：注释里解释性提到元素名是合理的）。
2. **渲染级断言**（`tools/DirPorter.UiProbe` 新增 `AssertDataGridsRendered`）：
   - 布局后遍历可视树：每个 `DataGridRow` 必须含 ≥1 个 `DataGridCell`；
   - 星号列 `ActualWidth < 8` 报"列塌陷"；
   - 失败返回非 0 退出码，可进发布检查清单。
3. **渲染图人工复核**：四张页面 + shell 的 PNG 快照（本次实测全部正常）。

## 2. P1 迁移页勾选语义（用户拍板：勾选 = 要迁移的条目）

原语义陷阱：勾选只用于「移除」，点迁移却执行**整个队列** 与扫描页（勾选 = 迁移这些）不一致。

新语义（与 Czkawka 等同类工具惯例一致）：

| 行为 | 实现 |
|---|---|
| 勾选 = 要迁移的条目；默认全勾选 | `QueueItem.IsSelected` 默认 `true`（构造即勾选） |
| `BuildPlan()` 只纳入勾选项 | `Queue.Where(q => q.IsSelected)`，`internal` 供测试断言 |
| 执行批次一次性快照 | `RunQueueAsync` 开跑前取 `runItems`；预检 / 计划 / itemMap / 取消回滚标记全部用同一快照，执行中改勾选不影响本批 |
| 全不勾选 → 明确提示 | 复用新键 `mig.noSelection`；`RunQueueAsync` 与 `PreviewAsync` 都拦 |
| 干跑预览同源 | `RenderPreview` 接收同批快照，杜绝"描述与实际不一致" |
| 「移除」按钮保留 | 作用于勾选项，加了 ToolTip 说明"不会执行迁移" |
| 队列区文案 | `mig.queueHint`：「勾选 = 要迁移的条目（默认全选）；双击行打开源路径。」 |

## 3. P2 横条两行布局 + 建链类型"展示式"分段控件

### 挤压事故根因（三重叠加）

① 右侧 `Auto` 列堆了约 741px 控件（下拉 150 + 复选框 226 + 两按钮 277 + 标签）；
② `*` 列（输入区）里标签 70px + 浏览按钮 79px 先占满；
③ TextBox 无 `MinWidth`，作为填充元素可被压到 **0 像素**（截图只剩一个"F"）。

### 新布局

```
┌ 一键迁移并建链 ───────────────────────────────────────────────┐
│ 一键迁移并建链  目标根目录 [输入框（弹性，MinWidth 220）] [浏览…] │
│ 建链类型 [目录联接 (Junction)] [目录符号链接]  □我已理解…      [一键迁移并建链] [仅加入队列（高级）] │
└──────────────────────────────────────────────────────────────┘
```

### 分段控件（SegmentedControl / SegmentedItem）

- 实现：`ListBox` + 横向 `StackPanel` ItemsPanel + 自定义 `ItemContainerStyle`
  （选中 = `AccentBg` 实底 + `AccentFg` 文字；hover = `ControlBgHover`；禁用 = 0.5 透明度）。
- 选 ListBox 而非 RadioButton 的理由：保持 `ItemsSource/SelectedItem` 绑定契约（零 VM 改动）、
  数据驱动（未来加第三种类型零 XAML 改动）、整体禁用一行搞定（`CanChangeLinkKind`）。
- 复用现有画笔，未新增颜色键。
- **顺序陷阱**：`SegmentedItem` 必须排在隐式 `ListBoxItem` 样式之后
  既有测试用 `IndexOf` 取第一处 `TargetType="ListBoxItem"`，放错位置会让「选中态」测试取错样式块。
- 迁移页同步替换（两页一致）；设置页保留下拉（表单语境惯例）；链接页保留下拉（5 个选项）。
