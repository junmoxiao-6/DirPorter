## 2. R4 验收口径：A/B 对账

**同源分别用引擎 A（robocopy）与引擎 B（CopyFileEx）复制，产物必须逐字段一致。**

判断用了四重证据（`R4_ParityTests.引擎A与引擎B_同源复制结果必须完全一致`）：

| # | 证据 | 说明 |
|---|---|---|
| ① | 各自与源做 `TreeComparer` 校验通过 | 文件数 + 总字节 + 逐文件 size/mtime/属性 |
| ② | 两个目标的**元数据指纹完全相同** | 相对路径 + 长度 + mtime ticks 的 xxHash3 聚合 |
| ③ | 目录集合完全相同 | 指纹只覆盖文件，目录需单独比 |
| ④ | 逐文件**字节级内容**相同 | 哈希过期等于没校验 |

为什么这是有效口径：两个引擎实现路径毫无共性（一个驱动外部进程 + 解析文本日志，一个直接调 Win32），产物仍逐字段一致 ⇒ "复制语义"被真正对齐了，而不是各自碰巧对了一半。

对账样本刻意包含：中文目录名、带空格文件名、深层嵌套、空目录、250KB 二进制块，并统一时间戳消除随机差异。

## 3. 引擎 B 的能力矩阵与降级边界

| 项 | 引擎 A（robocopy） | 引擎 B（CopyFileEx） |
|---|---|---|
| 并发 | `/MT:n`（进程内多线程） | 文件级并行（N worker） |
| 进度粒度 | 文件级（解析日志逐行） | **字节级**（`CopyFileEx` 进度回调，跨线程聚合） |
| 暂停/继续 | ✗（只能杀进程后重启，靠"已存在且大小/mtime 一致则跳过"增量续做） | ✓（在进度回调内阻塞，已复制数据不受影响） |
| DACL | ✓ `/COPY:DATSO` | ✓ 自实现 `SetNamedSecurityInfo` |
| 所有者/组 | 仅提权（`/COPYALL`，否则返回 16） | 仅提权（`SeRestorePrivilege` 需**已启用**） |
| 审计 SACL | 仅提权（同上） | 仅提权（`SeSecurityPrivilege` 需**已启用**） |
| ADS | ✓ | ✓（`CopyFileEx` 逐流复制，本机实测确认） |
| 稀疏 | ✓ | ✓（自实现，带安全阀） |
| EFS | 未测（能力声明保守为 false） | 默认**拒绝**解密复制；`--allow-decrypt` 显式开启 |

**降级必须显式**：非提权时引擎 B 的 `SecurityNote` 会写明"仅复制 DACL，未复制所有者/审计（需管理员 + 对应特权）"，并同时写入台账 `COPYING/note` 事件。绝不假装完整。

### 3.1 ADS 是"实测确认"而非假设

`CopyFileEx` 的进度回调带 `dwStreamNumber / StreamSize / StreamBytesTransferred` 参数，暗示它逐流复制。用例 `备用数据流_ADS_被保留` 把这个推断变成证据：写入 `file.txt:secret` 后复制，目标侧 `FindFirstStreamW` 仍能枚举出 `:secret:$DATA` 且内容一致。

### 3.2 稀疏保持的安全设计

`CopyFileEx` 会把"洞"写成真实数据，2GB 只占 10MB 的稀疏文件会被放大 200 倍。做法：

1. 先让 `CopyFileEx` 完成**完整字节复制**（此刻目标已是正确副本）；
2. 按源的 `FSCTL_QUERY_ALLOCATED_RANGES` 求"洞"区间；
3. 每个洞区间**先读目标确认全为 0**，确认通过才 `FSCTL_SET_ZERO_DATA`。

第 3 步是安全阀：即使范围解析有任何偏差，也**不可能把真实数据抹成零**——含非零字节的区域一律跳过并计入 `SkippedForSafety`。用例实测：源 8MB/逻辑、占用 256KB；目标同样保持稀疏，且**整文件逐字节内容一致**。

## 4. 本轮修掉的 3 个真实缺陷

### 缺陷 1（严重）：引擎 A 的"已复制文件数 / 进度"长期恒为 0

- **现象**：`R4_ParityTests` 断言 `FilesCopied` 一致时失败：A 报 0、B 报 7。
- **根因**：robocopy 的 `/LOG:` 文件是**系统 ANSI 单字节编码**（本机 cp936），不是 UTF-16。`/UNICODE` 只影响**控制台**，不影响日志文件。原实现按 `Encoding.Unicode` 读日志 ⇒ 每个 ASCII 字符被拼成 CJK 码点 ⇒ 逐文件行、中文错误行**全部解析不出来**。
- **影响面**：引擎 A 的 `FilesCopied`/`BytesCopied`/进度事件恒为 0；中文错误行也会漏检（退出码仍能兜住判定，但可观测性失真；UI 进度条对引擎 A 等于没有）。
- **修复**：
  1. 新增 `AnsiText`，用 `MultiByteToWideChar(CP_ACP)` 按系统 ANSI 代码页解码（含 UTF-16/UTF-8 BOM 自动识别）；
  2. 计数改为以日志末尾的**汇总块**为权威来源——只判断"行末 6 个 token 是否都是整数"，**完全不依赖本地化文案**，中英文日志都能过。
- **证据**：`R4_RobocopyLogTests` 用真实中文与英文汇总块各跑一遍；端到端用例断言 `FilesCopied == 3`、`BytesCopied == 源字节和`、二次运行为 `FilesSkipped == 3`。

### 缺陷 2（易踩）：`MultiByteToWideChar` 未声明 `CharSet.Unicode` → 输出全是 NUL

- **现象**：`AnsiText.Decode` 对纯 ASCII 输入返回 `"\0\0\0…"`。
- **根因**：`DllImport` 默认按 ANSI 编组，`char[]` 被当成 **1 字节** 数组写入。
- **修复**：显式 `CharSet = CharSet.Unicode`。已写进注释，避免以后有人"顺手清理"掉。

### 缺陷 3（脚本层）：PowerShell 5.1 + `$ErrorActionPreference='Stop'` + 原生命令写 stderr

- **现象**：中断恢复演练在第一个场景莫名中断，异常类型 `RemoteException` 且 **Message 为空**。
- **根因**：PS 5.1 在该策略下会把原生命令的 stderr 输出转成终止性异常。CLI 的进度条写在 stderr ⇒ 必然踩到。（此前"碰巧"没踩到，是因为进度回调走 `Progress<T>` 线程池异步投递，进程结束太快没来得及写。）
- **修复**：两个测试脚本里调用原生命令时**局部**把 `ErrorActionPreference` 降为 `Continue`；`move` 额外加 `--quiet`。
- **附带修复**：三个 `.ps1` 一律改为 **UTF-8 BOM** 保存。PS 5.1 对无 BOM 的脚本按系统 ANSI 解码，中文会变乱码并产生语法错误（提权脚本首次运行就是这样炸的）。

### 附：一处测试笔误

`R4_ParityTests` 首版把 A/B 的 `FilesCopied` 一致当作前提，但这是在缺陷 1 尚未修复时的错误预期。修正方式是先修实现、再用真实值断言——**不为通过而放宽断言**。

## 5. 备份保留策略（`BackupRetentionService`）

定位：`BACKUP_CLEANUP` 之后的**唯一删除入口**。三条不可违反的规矩：

1. **绝不删除台账**：`.migbak\.ledger` 长期保留、不自动清理（用户明确要求）。名称为 `.ledger` 的目录直接跳过。
2. **只删"位于 `.migbak` 之下"的目录**：删除前强制校验父目录叶名等于 `.migbak`，从结构上杜绝"参数写错 → 删掉用户真实目录"。
3. **走 `SafeTreeDeleter`**：停车目录内部可能含嵌套链接，普通递归删除会穿透链接删掉真实数据。

候选发现两条路：① 迁移记录索引（有明确完成时间，最可靠）；② 目录扫描（按 `_yyyyMMdd_HHmmss_xxxxxx` 解析创建时间，解析失败退化到目录时间并**标记为估算**）。

`RetentionDays < 0` 表示"永不清理"，直接返回空结果。清理成功后把迁移记录里的 `BackupPath` 置空，避免重复命中。

CLI：

```powershell
dirporter sweepbackups --days 7 [--root <目录>] [--all] [--dry-run] [--yes]
```

不带 `--yes` 默认只做演练。用例覆盖：到期删/未到期留/台账存活/演练不删/嵌套链接不穿透/结构闸门拒绝/负数永不清理/记录联动。
