## 1. 需求：每次启动应用时自动请求并获取管理员权限

### 实现（代码提权，而非清单提权）

GUI 入口 `Program.RunGui()` 在创建 WPF 应用**之前**检查提权状态：

```csharp
if (!elevation.IsElevated)
{
    var launch = elevation.LaunchElevated(string.Empty);   // runas 重启自身（无参 = GUI 模式）
    if (launch.Started) return 0;                          // 提权实例接管，本进程让位
    ElevationNotice = launch.Canceled ? (priv.elevationCancelled) : (priv.elevationFailed, err);
}
```

* **UAC 同意** → 提权实例启动 GUI（用户视角 = 启动时提权）。
* **UAC 取消 / 启动失败** → **降级继续运行**，界面顶部常驻**权限横幅**（含「以管理员身份重启」按钮），
  底部提示具体原因。绝不出现"程序起不来"。
* 语言化文案：横幅与提示均进 `LocalizationService`（中英同表）。

### 为什么保持 `asInvoker` 清单（显式偏离记录）

单 exe 同时承载 GUI 与 CLI。若写死 `requireAdministrator`：

1. 只读命令（`scan` / `inspect` / 干跑）与脚本管道调用会全部弹 UAC 甚至挂起；
2. 同一 exe 内无法提供"以普通权限运行"的降级路径；
3. R6 的"CLI 管道场景"验收项直接失效。

因此**提权由代码在 GUI 分支完成，CLI 保留 `--elevate` 手动开关**。
守卫测试：`GUI入口_必须包含自动提权分支`、`清单_必须保持asInvoker_否则CLI会弹UAC`。

## 2. 需求：点击目录后选中项变蓝、遮挡内容

### 根因（前一轮的认知错误）

上一版注释声称"Style 触发器的优先级高于模板触发器"——**错误**。
WPF 依赖属性优先级里 **模板触发器（TemplatedParent template triggers）高于样式触发器**，
而 Aero/WinUI 自带的 `ListBoxItem` / `DataGridCell` / `DataGridRow` / `ComboBoxItem` 模板里
都有 `IsSelected → SystemColors.HighlightBrush`（系统高亮蓝）的触发器：

* 只写 `Style.Triggers` 盖不住 → 选中行仍是系统蓝底；
* `DataGridCell` 在行内再叠一层蓝，与自定义单元格内容（路径链接、复选框）叠加后视觉全乱。

### 修法

四种控件的**选中态全部写进自己的 `ControlTemplate`**（`Themes/Shared.xaml`）：

| 控件 | 选中表现 |
|---|---|
| `ListBoxItem` | `SelectionBg` 浅蓝底 + `TextPrimary` 文字 + hover 浅底 |
| `DataGridCell` | 选中时**透明**（透出行底色，不再出现系统蓝块） |
| `DataGridRow` | `SelectionBg` 行高亮 + hover `ListRowAlt` |
| `ComboBoxItem` | `SelectionBg` + hover |

守卫测试：`选中态_必须写进ControlTemplate_才能盖住系统高亮蓝`（4 种控件）、
`选中态_不得再引用系统高亮画笔`。

> 顺带修掉一个真 bug：`ComboBoxItem` 样式在文件中**重复定义了两份**（新旧并存）。
> 隐式样式同 key 重复会让 WPF 资源字典加载行为不确定 —— R7 的
> "五个页面 + 主窗口 STA 构造"测试正是因此失败（这也是用户界面上"某些控件样式诡异"的潜在来源）。
> 已删旧版，只留带模板的新版。

## 4. 需求：区分 mklink 类型，默认目录联接，保留一键动线

### 架构（单一事实来源）

* `Core/Links/LinkKinds.cs`：类型解析/序列化收敛一处（CLI `--type`、设置持久化、记录回读共用），
  别名与 CLI 历史行为完全一致（`junction|j`、`symlink-dir|dirsymlink|d` …）。
  `CLI.TryParseKind` 改为委托它 —— 杜绝"CLI 认 dirsymlink 而设置只认 symlink-dir"这类静默分叉。
* `UiSettings.DefaultLinkKind`（默认 `junction`），损坏值回退目录联接。

### UI 三处暴露 + 一键动线保留

| 位置 | 作用 |
|---|---|
| **扫描页**一键横条 | 新增「建链类型」下拉（与其他控件同排），一键迁移立即用所选类型 |
| **迁移页**选项区 | 同款下拉 + 说明文本；**迁移执行中禁用**（引擎开跑时已按条目快照） |
| **设置页**通用卡 | 「默认建链类型」——改后同步迁移页当前选择并持久化 |

* 切换类型 → 队列里**尚未开始**（Planned）的条目随动；已成功/失败的保持原样（记录必须反映真实发生的事）。
* 目录符号链接在**无权限**时给出提前提示（`mig.linkKindNeedPrivilege`），
  不等到建链那一步才失败；权限到位（启动提权）后即恢复可选。
* 记录页「重建链接」同样使用默认类型（与迁移一致）。
* 迁移候选**只含目录级两种**（Junction / DirectorySymlink）——硬链接与文件符号链接不支持目录，
  不得出现在迁移建链选择里（有测试断言）。

## 5. 顺带修复的测试基建缺陷（发现的真实问题）

R9（同卷快速移动）的 5 个用例经**默认引擎真实跑批**，会写共享数据根的
`migrations.json` / `runs/`，但**不在串行集合、也从不还原** —— 残留累积到 19KB 后，
`R6 verify_无记录时成功返回` 随机失败；与 R8 并行时还会撞出
`IOException: file is being used by another process`（实测两次运行都有）。

修复：

1. `R9` 加入 `[Collection(DataRootSequentialCollection.Name)]`（与 R6/R8/R10 串行）；
2. 新增共享 `DataRootGuard`（`using` 语义快照/还原，含被占用文件的容错），
   R8 的私有实现收敛到它；R9 的 6 个跑批用例全部包 guard。

验证：清理历史残留后全量重跑 —— `444/444` 绿，且**跑完后数据根零残留**（migrations.json 不存在、runs/ 为空）。
