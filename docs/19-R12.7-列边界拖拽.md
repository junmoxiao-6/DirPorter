# R12.7：列边界双向箭头拖拽（相邻两列此消彼长）

## 需求

在每两列之间的分隔处按住并左右拖动，**只改变相邻两列**的空间分配；拖动方向与鼠标一致，宽度实时跟随；
不再出现"拖动一列、整排一起重排"。

## 实现

1. **恢复原生列宽拖拽**：共享 DataGrid 样式 `CanUserResizeColumns=True`，
   鼠标移到列头边界会显示系统 `SizeWE` 双向箭头光标，按住即实时拖动。
2. **相邻列联动**：`ElasticColumns` 监听每列 `Width` 的依赖属性变更（`DependencyPropertyDescriptor`，
   DataGrid 没有列宽变更事件）：
   - 记下"拖动前快照"，算出被拖动列的 `delta`；
   - 用 `SolveAdjacent(left, right, delta, leftMin, rightMin)` 纯函数求新宽度：
     右邻列让出/吞下同样的量，两者合计不变；触底时被拖动列回退，保证不突破各自 `MinWidth`；
   - **只调整邻列**（被拖动列已由原生拖动放到鼠标位置，避免二次叠加）。
3. **手动模式**：用户一旦手动拖过，该表进入 `ManualGrids`，窗口缩放/页面重排不再覆盖用户宽度；
   页面卸载或窗口重建后自动恢复"按权重铺满"。
4. 变更回调延迟到 `DispatcherPriority.Input` 执行，避免在布局/拖拽过程中改列宽造成重入。

## 验证

- 纯函数单测（4 例）：向右拖、向左拖、右列触底、左列触底，均断言"总宽不变 + 不破下限"。
- 独立 WPF 验证器 `tools/ColumnProbe`（新建，脱离主程序运行）：
  ```
  before=[261.2, 261.2, 261.2] sum=783.6
  grew=40 shrank=40 sumAfter=783.6 sumReflow=783.6 kept=True
  [OK] adjacent resize works
  ```
  含义：拖左列 +40 → 右列 −40，总宽不变；随后自动重排不会覆盖；方向与鼠标一致。
- 全量测试：**490/490 通过**。

## 已知问题（与本改动无关）

主 UI 探针（`DirPorter.UiProbe`）在当前环境会在第一页前收到"应用退出"信号而中止（无异常、无可疑堆栈，
已逐项回退验证：与列宽/样式/探针新增断言均无关）。列宽交互改由 `tools/ColumnProbe` 独立验证；
主探针的退出信号另行排查。
