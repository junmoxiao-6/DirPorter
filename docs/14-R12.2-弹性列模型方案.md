# R12.2 方案：弹性列模型 —— 消除「队列 / 已存在的链接 / 迁移记录」的右侧空白与滚动残留

> 触发：用户第五轮反馈。核心批评：**R12.1 只是"把固定列调窄了一点"，布局模型依然是刚性的**；
> 三张表最右侧存在"需要滚动才能到达的空白区域"；滚动机制易出 bug。
> 要求：① 明确各栏布局 ② 最右侧空白处理 ③ 左右移动标注的触发与自动左移 ④ 左右移动**不受任何限制**。

---

## 0. 现状诊断（为什么会"缩不到底、消不掉空白"）

**现有列模型 = 刚性混合列**：核心信息列（路径/来源/目标）是星列（可伸缩），
但状态/数字/操作等列是**固定宽**。这导致两个结构性问题：

1. **表格"最小需求" = 固定列合计**（如迁移队列 334px、记录表曾 670px）——
   当窗口比它窄时，表格**只能横向滚动**；滚动条一旦出现，就存在"滚动才能到达的区域"，
   用户感知到的"右侧一大块空白 / 锁定的范围"就来自这里。
2. **滚动状态残留**：窗口尺寸来回变化（拖大 → 拖小 → 再拖大）时，表格的横向滚动偏移
   可能保持在旧值——即使新宽度已经"放得下"，视图仍停在右侧，左侧/右侧留下
   **视觉空白**，需要用户再手动滚回去。这就是"左右移动机制太容易出 bug"的现场。

**结论**：R12.1 的"固定列瘦身"只是缓解（把阈值调低），**没有改变模型**。本轮做**结构性修复**。

---

## 1. 各栏布局：全弹性列模型（Elastic Columns）

**列规则（三张表 + 扫描结果表统一）**：

| 规则 | 说明 |
|---|---|
| **所有业务列 `Width="k*"`（比例星列）** | 窗口宽 → 所有列按比例拉伸；窗口窄 → 按比例收缩，**没有"刚性合计"** |
| **每列 `MinWidth`（可读下限）** | 收缩到再小就无法阅读的一条底线（如路径 110、状态 56、时间 88） |
| **不设 `MaxWidth`** | 列可无限拉伸铺满（"不受任何限制"的前提） |
| **文本列统一截断 + 悬停全文** | `TextTrimming=CharacterEllipsis` + `ToolTip`（共享样式 `TrimmedCell`）|

**关键性质**：表格"最小需求宽"从"固定列合计"降为 **ΣMinWidth（≈ 420–500）**——
只要容器达到这个宽度，**结构上就不可能出现横向滚动**（无横滚 = 无"滚动的空白"）。

**各表列模型**（比例 / 最小宽，实施时以探针实测微调）：

| 表 | 列模型 | ΣMinWidth（目标） |
|---|---|---|
| 迁移队列 | ✓30 / 编号1*(46) / 源2*(110) / 目标2*(110) / 类型1*(60) / 状态1*(60) / %1*(44) | ≈ 450 |
| 已存在的链接 | 链接路径2*(120) / 目标路径2*(120) / 类型1*(60) / 状态1*(60) / 操作1*(72) | ≈ 430 |

## 2. 最右侧空白处理

**"空白"的两个来源，分别从结构上消除**：

| 来源 | 消除机制 |
|---|---|
| ① "表格最小需求 > 容器" 造成的滚动空间 | 全弹性列把最小需求压到 ΣMin（≈ 480）≤ 最小窗口可视区 → **正常窗口下横滚物理上不存在** |
| ② 滚动到列尾后"其余皆为空白"的观感 | 弹性列**铺满容器**（星列吃满剩余宽），**"列宽合计 ≡ 表格可视宽"**，滚动到末端看到的是**最后一列本身**，其后无空白 |

**验收断言（探针自动化）**：`Σ列ActualWidth ≈ 表格ActualWidth（差 < 2px）` → 即"无右侧空白"。

## 3. 左右移动标注（水平滚动条）的触发与自动行为

**触发条件（唯一）**：容器宽度 < ΣMinWidth（仅出现在极端窄窗，660 最小窗口下应基本不可达）。

**行为设计**：

| 场景 | 行为 |
|---|---|
| 容器 ≥ ΣMin | **不出现滚动条**（表格永远完整显示，列宽随窗口实时伸缩） |
| 容器 < ΣMin | 滚动条出现；点击箭头 / 拖动滑块 / 滚轮横滚 → **即时、跟手地左右移动**；可到达两端任意位置 |
| **窗口尺寸变化（放大/缩小/来回拖动）** | 列宽即时重算；**当新宽度 ≥ ΣMin 时，滚动偏移必须自动收敛为 0** —— 这是 WPF `ScrollViewer` 的标准语义（extent ≤ viewport 时 offset 强制归零），全弹性模型下**天然成立**，不再有"缩回去还能滚、滚滚又见空白"的残留态 |
| 滚动位置 | **不做任何持久化、不缓存、不拦截**：每次布局以当前宽度为准 |

## 4. 「左右移动不受任何限制」的具体设计

1. **无上限**：列不设 `MaxWidth`；滚动范围 = 内容的自然范围，**不允许出现"能滚但滚不到"的截断**；
2. **不拦截**：不注册任何横向滚动事件的 `Handled` 处理；R12.1 的滚轮链（`WheelScrollChaining`）
   **只作用于纵向**（表格纵向到头才转交外层），**横向滚轮不受其影响**；
3. **不冻结**：尺寸变化时列宽与滚动范围同步重算（清掉旧偏移造成的"假空白"）；
4. **回归测试**（探针新增，自动化护航）：
   - 多尺寸矩阵（1600 / 1220 / 860 / 700 / 520 宽）：断言 ≤ΣMin 时 `ScrollableWidth==0`（无横滚）；
   - 极窄档（520 宽）：`ScrollToHorizontalOffset(∞)` 断言**能到达最右端**（offset == ScrollableWidth），再 `ScrollToHorizontalOffset(-∞)` 断言**能回到最左端**——"不受限制"的机器证明；
   - 拉宽档：断言列铺满（无空白，见 §2 断言）。

## 5. 实施范围与步骤

1. `Shared.xaml` 新增 `TrimmedCell` 文本样式（截断 + ToolTip）；
2. 四张表（migrate / link / history / scan）列定义改为"比例星列 + MinWidth + 截断样式"；
3. 探针：`narrow-*` 渲染增加**无横滚 / 列铺满 / 两端可达**三组断言（覆盖 §2/§4）；
4. 全量测试 + 探针 + 发布 0.1.5；docs 收档。

且宽度恢复后偏移自动归零**——"左右移动不受任何限制"已由机器证明。
