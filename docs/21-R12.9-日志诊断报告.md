# R12.9：日志诊断报告（2026-10-20 22:52~22:57）

## 一、崩溃：链接页粘贴带引号路径 → 整个应用退出（已修复）

### 证据

```
crash-20261020-225641-p35124.log
System.ArgumentException: 路径包含非法字符："F:\jun\Coze" (Parameter 'path')
   at PathNormalizer.NormalizeAbsolute(String path)
   at LinkService.Recommend(LinkRequest req)
   at LinkViewModel.Evaluate()
   at UiDebouncer.Flush()
   at DispatcherTimer.FireTick()
```

第二份日志（22:56:44）路径是 `"F:\jun\Coze`（只剩一个引号）——用户删了一个引号又试了一次，同样崩。

### 根因（三层叠加，缺一不可）

1. **Windows「复制为路径」产出带双引号的文本**（`"F:\jun\Coze"`），直接粘贴进输入框；
2. `PathNormalizer.NormalizeAbsolute` 把引号判为非法字符并抛 `ArgumentException`；
3. `LinkViewModel.Evaluate()` 由**防抖定时器**调用，没有 try/catch，
   `UiDebouncer.Flush()` 也没有 → 异常直达 `DispatcherUnhandledException` → 进程退出。

### 修复

| 层 | 改动 |
|---|---|
| 输入清洗 | `PathNormalizer.CleanInput`：去掉首尾空白与**成对或落单**的引号（`"` / `'`） |
| 页面 | `LinkViewModel.Evaluate` 包 try/catch，非法输入转成页面提示（`link.invalidPath`），选项置灰 |
| 页面 | `CreateCore` / `Inspect` / `Unlink` 同样先清洗 |
| 迁移页 | `AddManual` 入队前清洗 + `NormalizeAbsolute` 校验，非法时提示而不入队 |
| 兜底 | `UiDebouncer.Flush` 包 try/catch 并写崩溃日志（防抖回调不再能带崩应用） |

回归测试 `R18_PastedPathToleranceTests`：清洗 7 种形态、VM 层不抛、防抖回调不抛。
全量 **509/509**。

## 二、迁移失败：复制与校验都成功后，改名被拒（Win32 5）

### 证据（两次，同一源）

| 时间 | 源 → 目标 | 完成步骤 | 结果 |
|---|---|---|---|
| 22:52:29 | `C:\Users\31125\Coze` → `F:\jun\Coze` | OCCUPANCY_SCAN / TARGET_PREPARE / COPYING / VERIFYING | **RolledBack** |
| 22:53:12 | 同上 | 同上 | **RolledBack** |

```
把源目录改名为 C:\Users\31125\.migbak\Coze_20261020_225312_39f361 失败：
Win32Code=0x00000005 (5) 拒绝访问。
```

即：**数据已完整复制并通过校验，最后一步"把源目录改名"被系统拒绝**，随后引擎按设计完整回滚
（删除目标副本），15 秒复制 + 全量校验全部作废。

### 为什么占用扫描没发现

`OCCUPANCY_SCAN` 用的是 **Restart Manager**，它只认"注册了 RM 的应用 + 文件句柄锁"。
最常见的 5 号错误来源是**某进程把该目录（或其子目录）当作当前工作目录（CWD）**——
这既不是文件句柄锁，RM 也查不到，但会让 `MoveFile` 返回 `ERROR_ACCESS_DENIED`。
Coze 这类 Electron/Node 应用非常容易把 CWD 设在数据目录里。

> 顺带说明：现在 `C:\Users\31125\Coze` 已是指向 `F:\jun\Coze` 的联接（22:57:15 创建），
> 说明最后你自己用「链接」页建成了。若再对它点迁移，预检的 `SrcIsLink` 规则会拦截，不会自复制。

### 方案（建议，尚未实施）

**A. 复制前先做"改名探测"（低成本，立刻止血）**

在 `COPYING` 之前加一步 `PARKING_PROBE`：把源目录改名为 `源名.parkprobe-<随机>`，立刻改回。

- 成功 → 后续 PARKING 大概率成功；
- 失败 → **在复制之前**就报错，文案直接给可执行指引：
  「源目录无法改名（通常是有程序正在其中运行）。请完全退出 Coze 后重试。」

代价：毫秒级窗口内目录名短暂变化；若此时进程被杀，需要 `recover` 能识别 `.parkprobe-` 后缀（可加）。

**B. 改名失败不再一键回滚（高价值，改动较大）**

现在「失败即完整回滚」对改名这一步是不合理的——数据已经校验通过，回滚等于扔掉成果。应改为：

1. 状态新记为 `ParkFailed`（不回滚，目标副本保留，源目录不动）；
2. UI/台账明确写：「已复制完成（数据在 F:\jun\Coze，已校验），仅"源目录改名"未完成。
   关闭占用程序后点『继续』即可完成，**无需重新复制**」；
3. 「继续」= 从 `PARKING` 续跑（跳过 COPYING/VERIFYING），成功后接 LINKING；
4. `dirporter recover` 增加对 `ParkFailed` 的实际续做（现在只报告、不修复）。

工作量：引擎状态机 + 台账状态 + 迁移页按钮 + recover 命令，需要一轮完整回归。
**建议单独一轮做，不和本次发布混在一起。**

**C. 长期：占用检测升级**

RM 之外补两类检测：
- 进程 CWD 扫描（`NtQueryInformationProcess` 取 `ProcessParameters.CurrentDirectory`）；
- 尝试以 `DELETE` 权限打开目录句柄，失败即"不可改名"的强信号。

这样 `OCCUPANCY_SCAN` 才能真正拦住"5 号错误"，并列出具体进程名。
