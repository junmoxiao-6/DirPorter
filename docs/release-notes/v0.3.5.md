# v0.3.5

> 对比 v0.3.4。本次只修一个"会把迁移彻底做不成"的缺陷，不引入新功能。

## 对比 v0.3.4

### 修复

- **`--no-security` 对 robocopy 引擎完全无效**（严重）
  `RobocopyCopier.BuildArguments` 里写死了 `useCopyAll ? "/COPYALL" : "/COPY:DATSO"`，
  根本没读 `CopyOptions.CopySecurity`。于是在**非提权 / 受限令牌 / 沙箱**环境里，
  robocopy 仍对每个文件去复制所有者信息（`O` 开关需要 `SeRestorePrivilege`），
  结果每个文件报 `错误 5 (0x00000005) 正在将 NTFS 安全复制到目标文件中`，
  退出码 8 → 整批失败并**完整回滚**。

  实测（迁移 `PowerToys`，985 MB / 3002 文件）：**1376 项失败，已复制数据被全部清回滚**，
  迁移等于完全做不成；用户唯一的绕过办法是改用 `--engine native`。

- **干跑显示的复制开关与实际执行不一致**：`--no-security` 时干跑仍显示 `/COPY:DATSO`。

### 新增

- **安全信息复制失败时自动降级重试**：检测到 `NTFS 安全` / `NTFS Security` / `0x00000005` 类失败，
  自动改用 `/COPY:DAT`（数据 + 属性 + 时间戳 + ADS，不碰 DACL/所有者）重试一次，
  并通过"安全信息"提示明确告知**目标目录将继承目标卷权限**。用一次可接受的权限信息损失
  换回"迁移能成功"，而不是整体回滚。

## 行为变化

| 场景 | v0.3.4 | v0.3.5 |
|---|---|---|
| `--no-security` + robocopy 引擎 | 仍按 `/COPY:DATSO` 复制，非提权时大量 `错误 5`、整批回滚 | 真正使用 `/COPY:DAT` |
| 默认（未指定 `--no-security`）+ 非提权 | 失败并回滚 | 首次失败后自动降级 `/COPY:DAT` 重试，并提示权限未搬运 |
| 干跑"复制开关"文案 | 恒显示 `/COPY:DATSO` | 与实际开关一致 |

## 升级建议

**建议所有 0.3.4 及更早版本升级**：在非管理员权限下迁移 `AppData` 这类含系统属主的目录时，
旧版本会 100% 失败并回滚。

## 验证

- 全量测试 **546/546** 通过（新增 `R24_CopySecuritySwitchTests` 共 8 个用例：
  开关选择、`/XJ` 必带、错误识别、干跑文案）
- 端到端（真实迁移 + 真实 Junction）：

