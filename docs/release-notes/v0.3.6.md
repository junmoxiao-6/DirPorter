# v0.3.6

> 对比 v0.3.5。只改安全信息降级策略，不引入新功能。

## 对比 v0.3.5

### 改进

- **安全信息降级改为四级链，优先保住 DACL**
  v0.3.5 的降级是一步到位的 `/COPY:DATSO → /COPY:DAT`：一旦复制所有者被拒，
  **整份安全描述符（DACL + 所有者）全部丢弃**，目标目录改为继承目标卷权限。
  实际上用户真正在意的是 DACL（谁能访问），所有者只是"文件归谁名下"。
  现在改为逐级下探：

  | 档位 | 保留内容 | 触发条件 |
  |---|---|---|
  | `/COPYALL` | 数据/属性/时间戳/ADS + DACL + 所有者 + 审计 | 管理员令牌 |
  | `/COPY:DATSO` | 数据/属性/时间戳/ADS + DACL + 所有者 | 非提权默认 |
  | `/COPY:DATS` | 数据/属性/时间戳/ADS + **DACL** | 复制所有者被拒（错误 5） |
  | `/COPY:DAT` | 数据/属性/时间戳/ADS | DACL 也被拒（极少数） |

  即：**权限不变，只丢所有者**，比直接退回最低档安全得多。

- **降级提示写明每一档的得失**：提示里会给出「`/COPY*` → `/COPY*`，因为什么失败，当前保留了什么」，
  并附一句"如需完整保留属性，请以管理员身份重新执行"。

### 修复

- 降级重试不再无上限：到 `/COPY:DAT` 即停止（此前只判断一次，逻辑分散在两处 `if` 里）。

## 行为变化

| 场景 | v0.3.5 | v0.3.6 |
|---|---|---|
| 非提权 + 复制所有者被拒 | 直接降到 `/COPY:DAT`，DACL 也丢 | 先降到 `/COPY:DATS`，**DACL 保留** |
| 管理员令牌 | `/COPYALL`，缺 SeSecurityPrivilege 时退 `/COPY:DATSO` | 同上，但可继续退 `DATS`/`DAT` |
| 用户取消 | 不重试 | 不重试（同） |

## 升级建议

可选升级。如果你只用**双击 GUI**（程序会自动请求提权），几乎不会触发降级；
用 CLI 或拒绝 UAC 时，本版本能更好地保住目录权限。

## 验证

- 全量测试 **559/559** 通过（新增 `R25_SecurityDegradeLadderTests` 共 10 个用例：
  降级顺序、最低档不再降级、档位→开关映射、退出码 16 / 错误 5 / 文件被占用 / 取消 的判定）。
- 说明：`错误 5` 的**端到端复现**受环境限制——非提权下对普通用户数据执行 `/COPY:DATSO` 也能成功，
  只有在遇到异主文件时才失败（11-07 迁移 `PowerToys` 时实测 1376 项失败、整批回滚，即该场景）。
  本版本对"是否该降级""降到哪一档""开关是否正确"全部有单测覆盖。
