# v0.3.3

> 本仓库的首个正式 Release。如果你之前用的是本地构建的 0.3.0 ~ 0.3.2，
> 下面先列**相对 v0.3.2 的改动**，再列**自 v0.3.0 起的累积变化**。

## 对比 v0.3.2

### 修复

- **目标目录已存在时，提示信息不可操作**：以前只说"目标位置已存在同名且非空的目录"，
  用户不知道下一步该做什么。现在会明确给出两条出路：
  - 如果那份数据就是你之前搬过去的 → **不需要再迁移**，到「链接」页把源路径指向它即可（并给出两条完整路径）；
  - 否则 → 给目标改名，或先自行处理该目录内容（工具不会覆盖或合并非空目录）。
- **悬空链接容易被漏看**：链接总览页扫描完成后，会在标题右侧统计
  「共 N 个链接，其中 M 个目标已丢失（悬空）」并用红色加粗显示
  （以前只在表格的某一列写"悬空"，扫几十行很难注意到）。

## 相对 v0.3.0 的累积变化

### 新增

- **自动更新**（设置 → 一键更新）：一次点击完成「检查 → 下载 → 校验 SHA256 → 替换 → 自动重启」。
- **更新源支持 GitHub Releases**：填 `github:用户名/仓库名` 即可，无需自建服务器。
- **迁移备份保留策略接入界面**：启动时、每批迁移结束后、以及设置页「清理到期备份」按钮，
  都会按你设置的保留天数清理 `.migbak` 停车目录（此前只有命令行能触发，界面设了也不生效）。

### 改进

- **自更新改用程序自身执行**：主进程把副本放到临时目录，由它等主进程退出后
  **原子替换** exe 再重启（先写 `.new` 并校验大小，再一次性改名）。
  不再生成 `.cmd` 脚本，也不再依赖 `tasklist`；替换失败不会损坏现有程序，日志在
  `%ProgramData%\DirPorter\logs\update.log`。
- **更新检查不再受 GitHub API 限流影响**：优先读
  `releases/latest/download/latest.json`（固定重定向地址，不走 API、无 60 次/小时限制），
  该附件缺失时才回落到 API。
- **列宽拖拽重做**：鼠标移到列头边界出现左右双向箭头，拖动时**相邻两列此消彼长**（总宽不变）；
  拖过之后该表进入手动模式，窗口缩放不会被自动重排覆盖。

### 修复

- 链接页粘贴带引号的路径（资源管理器「复制为路径」的产物）会导致**整个程序退出**。
  现在会自动去掉首尾引号，并在页面内提示而不是崩溃。
- 迁移完成后源目录仍在父级 `.migbak` 留下副本（观感像"复制"而非"剪切"）。
  默认改为迁移成功后立即删除该副本。
- 保留备份设为 1 天却不清理的问题（原因：界面从未触发保留策略）。
- 硬拒绝项只显示一句「存在硬拒绝项，无法继续」，不说明是哪一项。

### 变更

- 「一键迁移」页更名为「**一键迁移建链**」；「迁移」页只做迁移（不建链），
  成功后提供「去建链」跳转并自动预填。
- 迁移页新增队列单条「移除」。
- 迁移队列的列宽改为程序统一计算，右侧不再出现空白。

## 安装

下载 `dirporter.exe`（免安装单文件，约 65 MB，自包含 .NET 运行时），双击即用。
同一个 exe 也支持命令行：`dirporter.exe --help`。

SHA256 见本 Release 附件旁的说明，或 `latest.json` 里的 `sha256` 字段。
