# R12.6：迁移＝剪切 + 检查更新（0.1.8）

## 一、迁移语义核对结论

引擎步骤：`COPYING → VERIFYING → PARKING（源目录改名到父级 .migbak）→ LINKING（可选）→ DONE`。

- **源位置本身是"剪切"**：成功迁移后源目录不再存在（被改名走）；纯迁移（不建链）源路径直接消失。
- **但旧默认 `KeepBackup = true`** 会把源目录副本留在父级 `.migbak` 里 7 天（回滚兜底）——
  磁盘上实际存在**两份数据**，观感等价于"复制"。

### 修改

- `KeepBackup` 默认改为 **false** → 迁移成功后 engine 的 `BACKUP_CLEANUP` 立即删除停车副本：
  只保留目标一份数据，源位置与其父目录**不留残余**（真正剪切）。
- 复选框改名「保留备份（可回滚）」并加说明：勾选才保留 N 天，用于回滚。
- 回归测试：`默认不保留备份_即剪切语义`、`纯迁移后_源位置与停车区都不留第二份数据`。

## 二、检查更新

**发布清单**（静态 JSON，可放 GitHub Releases / 对象存储 / 任意静态托管）：

```json
{
  "version": "0.1.9",
  "url": "https://example.com/dirporter/0.1.9/dirporter.exe",
  "sha256": "…",
  "notes": "修复与改进说明"
}
```

- 地址来源：设置页「更新清单地址」；留空时读环境变量 `DIRPORTER_UPDATE_URL`。
- 设置页新增「检查更新」卡片：显示当前版本 → 检查 → （有新版时）显示版本/说明 → 「下载并安装」。
- 下载到临时目录并校验 SHA256；随后写一个临时 cmd：等待本进程退出 → 覆盖 exe → 启动新版本。
  覆盖失败（安装目录只读 / 非管理员）时明确提示手动替换。

### 注意（部署侧）

- 清单与 exe 必须能被终端用户匿名访问（HTTPS）。
- 每次发版记得同步更新清单的 `version` / `url` / `sha256`；`sha256` 可由
  `sha256sum dirporter.exe` 得到，建议一直填，防止下载被截断或篡改。
