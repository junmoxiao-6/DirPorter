# R12.1 自由缩放 · 滚轮滚动 · 数据目录（第五轮反馈）

> 用户反馈三问题：① 窗口缩到一定尺寸卡住（怀疑"模块右侧空白锁定范围"）
> ② 滚轮无响应（只能拖滚动条）③ ProgramData\DirPorter 与 .migbak 能否移盘。
> 版本 0.1.4 ｜ 验证：探针实测数据对比 + 全量测试 + UiProbe 断言。

---

## 问题一：窗口自由缩放

### 根因（实测数据，非猜测）

探针（UiProbe）在 860×540 窄窗下逐页实测"页面期望宽"（DesiredSize），视口约 635px：

| 页 | 修复前 | 元凶（实测） |
|---|---|---|
| scan | 719 | 表格固定列合计 629.6（风险列 230 最肥） |
| migrate | **842** | ①进度卡"按钮排+复选"同行并排 761 ②类型选择器在双列右列（两列期望相加） |
| **link** | **1251** | 推荐长文 738 不换行（`TextWrapping` 缺失）+ 双列相加 |
| quick / history | 618 | 达标 |

**系统性根因**：WPF 没有响应式布局——**双列 Grid 的"期望宽" = 左右两列期望之和**；
行内 N 个元素并排 = 期望相加；长文本不换行 = 全文宽成为整页的"最低需求"。

### 修复

1. **窗口最小尺寸 820×540 → 660×480**；PageHost MinWidth 560 → 420（页内滚动兜底）。
2. **四表固定列瘦身**：scan 风险 230→150、操作 120→100、大小 100→90（表格期望 651→542）；
   migrate 类型 142→110、状态 112→96；link 类型/状态 140→110。
3. **migrate 双列收敛**：类型选择器提升为通栏（不再参与"左+右相加"）；
   进度卡"按钮排"与"确认复选"拆成两行（761→531）。
4. **长文本换行修复**（同类陷阱第三次出现，前两次：R11 横条、R12 scopeHint）：
   link 页"推荐"文本 738→420（Wrap+MaxWidth）、"受限权限"文本 486→420、能力矩阵 Reason 列限宽 260；
   migrate 同卷提示 430→360。
5. **scan 按钮排瘦身**：全选/清除选择归位到结果区（控制区按钮期望 380→230）。

### 验证数据（修复后，视口 635）

| 页 | 修复后 | 效果 |
|---|---|---|
| scan | 654 | ≥690 窗口即无横滚 |
| migrate | 658 | ≥690 窗口即无横滚 |
| link | 931 | ≥1000 窗口无横滚；更小可滚动查看（双列下限所致，接受） |
| quick / history | 618 | ≥660 窗口无横滚 |

**结论**：≥1000 宽的窗口下所有页面完全无横向滚动；660（最小）下所有页面可滚动查看、布局不塌。

## 问题二：鼠标滚轮无响应

**根因**：页面内容在主 ScrollViewer 内，表格/列表自带内部滚动器——鼠标悬停在表格上时，
滚轮事件可能被内层消费或吞掉（部分控件在无滚动范围时的处理不一致），用户体感"滚轮完全没用"。

**修复**：`Services/WheelScrollChaining.cs` 附加行为（挂在 Shared.xaml 的 DataGrid / ListBox 隐式样式上，一处生效全局）：
- 内层还有滚余量 → 放行（保持"先滚表格"的自然顺序）；
- 内层到头 / 无范围 → 转交最近的外层滚动容器并标记已处理（避免双重滚动）。

**验证**：UiProbe 新增"滚轮链实测"（RaiseEvent 模拟滚轮 + 断言外层偏移变化）→ `[OK] 滚轮触发了外层滚动`。

## 问题三：数据目录移盘（说明性回答）

### `%ProgramData%\DirPorter`（软件本体数据：台账 runs / 迁移记录 / 日志 / 备份索引 / tmp）

**支持两种移盘方式**：

| 方式 | 做法 | 评价 |
|---|---|---|
| **环境变量（推荐）** | 设置 `DIRPORTER_DATA_ROOT=D:\DirPorterData`（系统或用户环境变量），重启程序 | 官方支持（代码内建：优先读取、不可用时自动降级并提示）；干净可回退 |
| Junction | 关程序 → 把目录**移动**到新位置 → `mklink /J "C:\ProgramData\DirPorter" "D:\DirPorterData"` | 程序无感；注意 ProgramData 机器级权限继承、操作前备份 |

注意事项：
- 环境变量方式需**先迁移现有数据**（复制 → 校验 → 再切换；旧目录保留几天）；
- Junction 方式必须**先关闭程序**（目录被占用时无法移动）；建议管理员操作；
- 两者都不要在"有未完成迁移任务"时操作（runs 里可能有进行中的恢复日志）。

### `C:\Users\...\AppData\Local\.migbak`（**不是**软件本体数据！）

**它是"停车目录"**：迁移某目录时，在**源目录的父目录**下自动生成的**备份区**
（回滚兜底 + 台账归档，默认保留 7 天、自动清理到期目录，`.ledger` 子目录长期保留）。

- 迁移 A 盘的东西 → 在 A 盘产生 `.migbak`；它是**跟着被迁移内容走**的临时数据；
- **不建议 Junction/移盘**：回滚与恢复逻辑依赖"同盘位置约定"，挪走会破坏兜底语义；
- **正确处置**：无需理会（到期自动清理）；如需立即回收空间，可在确认无待回滚任务后
  清理其中的旧目录，但**保留 `.ledger`**（台账归档）。

## 附：探针调试插曲（内部记录）

本轮探针一度稳定崩在"第二个页面构造：应用程序对象正在关闭"。抓凶结论：
无头宿主里 `Application` 的 `OnStartup` 被触发（单实例逻辑）→ 随后幽灵窗口的关闭
在 `ShutdownMode.OnLastWindowClose`（默认）下把应用送进关闭流程（WPF 的"最后窗口关闭即退出"）。
修复：探针显式 `ShutdownMode = OnExplicitShutdown`（无头宿主绝不该自动关机）。
教训：**无消息循环的 WPF 宿主里，默认 ShutdownMode 是个陷阱**；另：探针与用户正在运行的
dirporter.exe 无冲突（数据根隔离 + 单例互不影响）。
