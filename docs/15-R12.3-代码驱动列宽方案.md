# R12.3 方案：代码驱动列宽（确定性铺满）+ 全局滚轮兜底（设置页）

> 触发：第六轮反馈四张截图 —— 四表**列全部压到 MinWidth**、右侧 700-900px 空白、
> "左右移动"失效；另：**设置页滚轮无效**。
> 方案性质：放弃"依赖 WPF 星列算法"的间接方案，改为**代码确定性计算列宽**。

---

## 0. 为什么 0.1.5 的"星列方案"在真实窗口上失效

**实测事实（截图 + 探针交叉验证）**：

| 观察 | 数值 |
|---|---|
| 表格控件宽（行背景/表头延伸到的宽度） | ~1240px（窗口内容区全宽） |
| 列宽合计（每列恰好=MinWidth：路径130/大小52/文件44/已迁44/风险68/操作74…） | scan ≈ 442、migrate ≈ 424、link ≈ 398、history ≈ 490 |
| 表格内部滚动视口 | **= 列合计**（444 ≈ 442，而不是表格宽 622/1240） |
| 可滚动量 | **0**（列合计 < 表格宽，无需滚动 → "左右移动"失效正是这个原因） |

**结论**：`DataGrid` 的星列分配在"页面 DataTemplate 重建 / 延迟布局"时，
以"某次极小宽"为基准算出了 MinWidth，**之后表格变宽不再重算** —— 列宽被"固化在最小值"，
剩余宽度变成右侧空白。R12.2 的探针断言"列合计 ≈ 内部视口"恒成立（视口等于内容宽），
**因此没有暴露该缺陷**（这是本轮必须修正的验证设计）。

## 1. 核心方案：`ElasticColumns` 附加行为（代码驱动列宽，不依赖星列算法）

**实现**（新文件 `Services/ElasticColumns.cs`）：

1. 附加属性 `ElasticColumns.Enabled="True"` + `ElasticColumns.StarWeights="4,1,1,1,2,1"`（每列的比例权重，与 XAML 列声明一一对应）；
2. 挂 `SizeChanged` + `Loaded` + `LayoutUpdated`（节流）：
   ```
   可用宽 = 表格 ActualWidth − 固定宽列(勾选 30) − 2（边框）
   各列宽 = clamp(可用宽 × 权重 / Σ权重, 该列 MinWidth, ∞)
   若 Σ(各列宽) < 可用宽 → 把差额按权重补给"核心列"（保证总和 == 可用宽）
   若 ΣMin > 可用宽 → 全部取 MinWidth（此时才允许横向滚动）
   ```
3. 用 `SetCurrentValue(DataGridColumn.WidthProperty, new DataGridLength(像素, Pixel))` 逐列赋值 —— **确定性、与 DataGrid 内部算法无关**；
4. **不设任何上限**：窗口拉宽多少，列就多宽（严格满足"不受任何限制"）；
5. **列可手动拖动**（`CanUserResizeColumns` 保持），但下一次尺寸变化会重新均摊（**取舍：填满优先**）。

**列权重表**（整数权重，替代小数星号）：

| 表 | 权重（与列序对应） | ΣMin |
|---|---|---|
| 扫描结果 | 4,1,1,1,2,1（+✓固定30） | 442 |
| 迁移队列 | 1,3,3,1,1,1（+✓固定30） | 424 |
| 已存在的链接 | 2,2,1,1,1 | 398 |
| 迁移记录 | 2,1,2,2,1,1,1 | 490 |

## 2. 验证设计（修正 R12.2 的错误判据）

**新断言基准改为"表格控件宽"**：

- `|列合计 − 表格.ActualWidth| < 4px` → 铺满（右侧无空白）；
- `表格内部 ScrollableWidth == 0`（≥ΣMin 的容器）→ 无横向滚动；
- 覆盖三档：**主窗口 1220×820（用户现场）**、860×540、**660×480**；
- 极窄/强制窄：`ScrollToHorizontalOffset` 两端可达（"不受限制"回归）；
- 拉宽归零：窄→滚到最右→拉宽 → offset == 0。

## 3. 设置页滚轮无效

**方案**：滚轮统一入口 —— 在主内容 `ScrollViewer` 上挂 `PreviewMouseWheel`（隧道最早且能覆盖"无内层滚动者"的页面如设置页）：

```
原始源向上找最近的内层可滚动控件（DataGrid/ListBox/TextBox 内部 ScrollViewer）：
  · 找到且该方向还有余量 → 放行（内层自己滚）
  · 没有 / 到头 / 无范围 → 手动滚动外层 + Handled
```

- 现有 `WheelScrollChaining`（挂 DataGrid/ListBox）保留作为互补；
- 探针新增：设置页"内容高 > 视口"断言 + 模拟滚轮断言外层滚动。

**说明**：若"设置页内容本就不超高"，滚轮无效属正常（无可滚内容）——探针会给出该页
`内容高 vs 视口高` 实测，明确根因后再决定是否需要额外处理。

## 4. 实施步骤

1. `Services/ElasticColumns.cs`（新）+ 四表挂附加属性（删除星列声明，改为 `Width="Auto"` 由代码接管）；
2. `MainWindow.xaml` 的主 ScrollViewer 挂 `PreviewMouseWheel` 统一入口；
3. 探针：修正断言基准 + 三档覆盖 + 设置页滚轮/内容高度诊断；
4. 全量测试（含新增静态守卫：四表必须声明 ElasticColumns.StarWeights）；
5. 发布 0.1.6（沙箱中心仍会拦自动发布 → 用户终端跑 `publish.ps1`）。

# 第二部分：功能职责严格拆分（迁移 / 建链 / 一键）

> 用户要求：「迁移就只有迁移功能，建链就只有建链功能，已经有一键迁移建链了」；
> 「一键迁移」改名为「**一键迁移建链**」；迁移页去掉一切建链相关功能。

## 5. 职责矩阵（拆后）

| 页面 | 名称（改后） | 职责 | 明确不含 |
|---|---|---|---|
| 一键迁移建链 | **一键迁移建链**（原"一键迁移"） | 多源 → 目标根：**复制 + 校验 + 建链** 一步到位 | — |
| 迁移 | **迁移** | 只搬运数据：**复制 + 校验 + 源移除**（不建链） | 建链类型选择、建链动作、一键入口 |
| 链接 | 链接（不变） | 只建链/改链/删链（手动指定链接路径与目标） | 迁移入口 |
| 扫描 | 扫描（不变） | 只分析与入队 | 迁移执行 |

## 6. 迁移页（纯迁移）变更清单

### UI
- **删除**「建链类型」通栏区（`LinkKindOptions` 选择器 + `LinkKindHint` + `scopeHint`）；
- 按钮文案 `mig.run`：「迁移并建链」→「**开始迁移**」；页面标题 `mig.title`：「迁移与建链」→「**迁移**」；
- **新增醒目提示**（`mig.pureHint`）：「本操作只搬运数据、**不建立链接**——完成后原路径将不再存在。
  需要保留原路径请使用「一键迁移建链」。」
- 队列/进度/预览区保持；`mig.acknowledge`（风险确认）保留。

### 引擎与执行链
- `MigrationPlanEntry` 新增 **`CreateLink`（bool，默认 true）**——比把 `LinkKind` 改可空侵入小、对现有调用零破坏；
- `MigrationEngine`：`LINKING` / `LINK_VERIFY` 两个阶段在 `CreateLink == false` 时**直接跳过**（状态机：COPY_VERIFY → PARKING → DONE）；
  纯迁移语义 = 源目录移入 `.migbak` 停车区后**清除** → 源路径消失、目标持有数据；
- 执行入口统一为 `MigrateViewModel.RunQueueAsync(bool createLink)`：
  - 迁移页 `StartCommand` → `createLink: false`；
  - 一键页 → `createLink: true`（既有行为，`ReplaceQueue` + 透传目标根）。

### 台账 / 记录 / 扫描联动
- `MigrationRecord.LinkType` 纯迁移时写 **`None`**（或空），记录页/健康列显示「未建链接」（沿用 R12.1 文案）；
- **扫描页"已迁移"判定升级**：当前只认"源是链接"。纯迁移后源不存在但数据已搬走，
  判定改为 **`源是链接` 或 `源不存在 && 台账存在该源的 done 记录 && 目标仍存在`**（避免误报"否"）。

### 受影响的测试（需同步改造）
- R10「迁移页_四种全展示…」→ 改为「迁移页**不含**建链控件」守卫 + 一键页保留四展示断言；
- R11「迁移页必须用分段控件」→ 仅一键页；
- R12「迁移页与设置页默认类型」→ 仅设置页；
- R10「三页面提供类型选择器」→ 改为「一键页 + 设置页」；
- **新增**：纯迁移 E2E（源消失、目标有数据、**源路径不存在**、台账 `LinkType=None`）；
- 既有引擎/端到端测试（走一键页或默认 `CreateLink=true`）应保持全绿。

## 7. 待确认的关键语义

**纯迁移 = 移动**：迁移后源目录被移除（数据只在目标处）；**不是复制**（不保留源）。
若用户实际想要"复制一份到目标、源保留"，需另行定义"复制模式"（本方案不含）。
