# R12.12：自动更新重构（0.3.2）

## 上一版（0.3.1）的三个硬伤

| 问题 | 后果 |
|---|---|
| 只走 `api.github.com/releases/latest` | 匿名限流 60 次/小时/IP；国内经常连不上 |
| 用临时 `cmd` 脚本替换 exe | 安全软件爱拦；`copy` 覆盖到一半失败会把 exe 弄坏（**更新失败变砖**） |
| 替换脚本靠"复制失败就重试"判断进程退出 | 没有日志，失败后用户完全不知道发生了什么 |

## 现在的做法

### 1. 更新源：Release 附件优先，API 兜底

```
首选  https://github.com/<owner>/<repo>/releases/latest/download/latest.json
回落  https://api.github.com/repos/<owner>/<repo>/releases/latest
```

- `releases/latest/download/<文件名>` 是 GitHub 的**固定重定向地址**，不走 API、**没有限流**，也不需要 token；
- 只要发版时把 `latest.json` 也作为附件上传，客户端就走这条路；
- 万一某次忘了传，自动回落到 API（不会因此失效）。

### 2. 更新执行器：程序自己就是 updater

```
主进程：下载 → 校验 SHA256 → 把自己复制到 %TEMP%\dirporter-updater-*.exe
        → 用 apply-update 参数启动这份副本 → 退出
更新器：等主进程退出 → 把新文件写成 dirporter.exe.new → 校验大小
        → MoveFileEx 原子替换 → 启动新版本 → 写日志
```

- **不再生成任何 cmd/bat**：不受企业安全策略影响，无控制台窗口、无编码问题；
- **原子替换**：先写 `.new` 再一次性改名，任何一步失败都不会破坏现有 exe；
- **有日志**：`%ProgramData%\DirPorter\logs\update.log`；
- 单文件 exe 自包含，不需要任何额外组件。

### 3. 校验更严

- 清单里带 `sha256` 就必须匹配，否则直接判失败并删除下载文件；
- 替换前再比一次文件大小，防止写入中断。

## 发版流程（GitHub）

1. 改 `Directory.Build.props` 的 `<Version>`；
2. 跑 `publish.ps1` 产出 `dist\<版本>\dirporter.exe`；
3. 跑 `tools\make-release.ps1 -Notes "本次更新说明"` 生成 `dist\<版本>\latest.json`；
4. 网页建 Release（tag `v<版本>`），**必须上传两个附件**：

| 文件 | 作用 |
|---|---|
| `dist\<版本>\dirporter.exe` | 程序本体（文件名固定） |
| `dist\<版本>\latest.json` | 客户端首选清单（决定是否走无限流通道） |

## 实测

端到端验证更新执行器（不同大小的两个 exe 互相替换）：

```
替换前 target: 150,016 字节
新版本:        180,736 字节
EXIT=0
替换后 target: 180,736 字节      ← 已替换，且无 .new 残留
日志：替换成功。
```

全量测试 **526/526**。
